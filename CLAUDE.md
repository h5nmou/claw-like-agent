## Project Overview

Universal Agent Engine — an autonomous agent trust-network PoC demonstrating carrier-grade (SKT infrastructure) autonomous collaboration through multi-channel hotel booking synchronization. Korean-language project (commits, UI text, scenes).

## Running the Project

```bash

pip install -r requirements.txt

# Run all 5 servers at once (recommended)
python3 run.py

# First run: visit http://localhost:8004, enter PIN "1234" + approve
```

## Architecture

### 4-Element Trust Network (5 microservices)

| Service | Port | Role |
|---------|------|------|
| Engine (`core/engine.py`) | 8000 | Main agent: LLM brain, webhook receiver, SSE dashboard |
| Site A (`mocks/site_a.py`) | 8001 | Booking source, triggers webhooks to Engine |
| Site B (`mocks/site_b.py`) | 8002 | Guardian agent, requires RS256 JWT + VPAL header |
| Telco Server (`mocks/telco_server.py`) | 8003 | Trust server, RSA policy engine, issues JWTs |
| Telco App UI (`mocks/telco_app_ui.py`) | 8004 | Manager approval UI for onboarding |

### Core Agent Loop (engine.py)

PERCEIVE (webhook) → REASON (LLM thinks with tools) → ACT (execute tools) → LOOP (repeat until done) → Log (SSE broadcast)

### Key Modules

- **`core/brain.py`** — OpenAI function-calling interface; maintains message history with system prompt
- **`core/executor.py`** — `@tool` decorator auto-registers functions; docstring → JSON Schema for OpenAI; Progressive Disclosure schemas; quality tracking
- **`core/onboarding_manager.py`** — RSA keypair generation, 6-step handshake with Telco, delegation certificate
- **`core/skill_factory.py`** — Enterprise Skill Factory 2.0: DISCOVERY → SYNTHESIS (LATM Maker model + Iterative Prompting, max 5 retries) → PEER REVIEW → SECURITY GATE → REGISTRATION
- **`core/skill_registry.py`** — Progressive Disclosure: `load_metadata()` (index-only) + `activate(skill_name)` (on-demand code load); efficient for 1000s of skills
- **`core/skill_security.py`** — 7-stage security gate: critical/high/medium patterns + prompt injection defense + allowlist policy + AST + code hash
- **`core/skill_versioning.py`** — Semantic versioning with quality-gated auto-rollback; `v*.meta.json` per-version quality metadata; OpenClaw SKILL.md standard
- **`core/skill_quality.py`** — Multi-signal quality evaluator: execution error rate + semantic alignment + security score + performance; grade A-F
- **`core/skill_healer.py`** — 4-stage self-healing: Restart → Health Check → AI Doctor (LLM patch) → Escalation (Telegram alert)
- **`core/memory.py`** — Session event logging
- **`core/mcp_client.py`** — Phone-MCP remote tool discovery
- **`core/telegram_client.py`** — Telegram bot polling

### Tool Registration Hierarchy

1. Core tools (`core/executor.py`): built-in utilities
2. Scene tools (`tools/*.py`): site_a_api, site_b_api, telco_auth_api
3. Generated skills (`generated_skills/*.py`): auto-generated by Skill Factory
4. Phone-MCP tools: dynamically discovered at startup

### Scene System (`scenes/*.md`)

All `.md` files in `scenes/` are loaded and concatenated into the LLM system prompt at startup. Each scene defines role/goal/rules for a capability domain (hotel sync, communication, skill factory, phone booking).

### Auth Flow Pattern

Site B returns 401 → LLM calls `get_telco_auth_token()` → Telco checks policy, issues RS256 JWT + VPAL session → LLM retries with `block_site_b_dates_with_token(token, vpal_session_id)` → Site B verifies signature + VPAL match → 200 OK

### Enterprise Skill Factory 2.0 Pipeline

Missing tool detected → `create_new_skill()` → web search (DISCOVERY) → LATM Maker model generates code → Iterative Prompting loop (max 5, error + env feedback) → Peer Review (code quality + safety) → 7-stage Security Gate (prompt injection + allowlist) → save with version metadata → quality evaluation (A-F grade) → register in executor → execute immediately

**Self-Healing** (automatic on consecutive failures): Stage 1 Restart → Stage 2 Health Check (env vars, deps, network) → Stage 3 AI Doctor (LLM patches code in-place) → Stage 4 Telegram escalation

**Quality Gate**: if avg quality < 40/100 → auto-rollback to last stable version via `skill_versioning.py`

## Key Conventions

- **Async-first**: all tools use `httpx.AsyncClient`, all handlers are async
- **Tool docstrings are API contracts**: first line = summary, `Args:` section = parameter schema for OpenAI function calling. Type hints required.
- **Tools return dict or string** for LLM context consumption
- **`_pending_original_context`** global injects user's original task into webhook events to prevent task abandonment after booking sync
- **Prompt injection defense**: all `/chat` and `/webhook` inputs are scanned by `SkillSecurityGate.scan_user_input()` before processing
- **LATM models**: `SKILL_MAKER_MODEL` (default: gpt-4o) for code synthesis + peer review; `SKILL_USER_MODEL` (default: gpt-4o-mini) for lightweight execution
- **Korean UI/commits**: project uses Korean for user-facing text and commit messages

## Environment

Required in `.env`: `OPENAI_API_KEY`. Optional: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_USER_ID`, `SMTP_*`, `NAVER_ID/PW`, `MCP_SERVER_URL`, `OPENAI_MODEL` (default: gpt-4o).

RSA keys (`.agent_private.pem`, `.agent_public.pem`) and certificates (`.agent_cert`) are generated during onboarding — not committed to git.
